# 專案範本檔匯入格式

> 適用版本：`1.46.0` 起。匯入入口：**專案視窗 › 從範本建立 › 匯入範本檔…**
> 可直接匯入的範例在 [`docs/project-templates/`](./project-templates/)（企業行銷、教育訓練、財務會計各 2 個）。

專案範本是「分階段提示詞流程」的藍圖：從範本建立專案後，專案的「階段流程」分頁會依序列出每個步驟，
你把「已帶入專案主題與前面步驟產出」的提示詞複製給 AI、把產出貼回來、標記完成，再進下一步。
匯入的範本會成為**自訂範本**（可刪除、可再被「另存為範本」覆蓋流程）；內建範本是唯讀的，不會被動到。

## 1. 匯入方式

1. 專案視窗 › **從範本建立**，按左下角 **匯入範本檔…**。
2. 選一個 `.json` 檔（UTF-8，可含 BOM；上限 10 MB）。
3. 成功後範本清單會出現新的「自訂」範本，並自動選取第一個；畫面顯示匯入幾個、略過幾個。

匯入一律**新增**：每個範本都會產生新的 `id`，所以重複匯入同一個檔案會得到兩份，不會覆蓋任何既有範本。

## 2. 檔案結構

建議的最上層格式：

```json
{
  "format": "platter-project-templates",
  "formatVersion": 1,
  "templates": [
    {
      "name": "範本名稱",
      "description": "給使用者看的說明（選填）",
      "stages": [
        {
          "title": "階段 1：階段名稱",
          "steps": [{ "title": "步驟名稱", "prompt": "提示詞全文，可用 {{topic}}" }],
          "relatedPrompts": [{ "title": "輔助提示詞名稱", "prompt": "提示詞全文" }]
        }
      ]
    }
  ]
}
```

最上層也接受另外兩種寫法（但仍會被當成同樣的內容驗證）：

- 範本陣列：`[ { "name": …, "stages": … }, … ]`
- 單一範本物件：`{ "name": …, "stages": … }`

若有 `format` 欄位，值必須是 `"platter-project-templates"`，否則整份檔案視為格式錯誤。
`formatVersion` 目前固定為 `1`（保留給未來格式升級，現在不影響匯入）。

### 欄位說明

| 位置                    | 欄位             | 必填 | 說明                                                                                           |
| ----------------------- | ---------------- | ---- | ---------------------------------------------------------------------------------------------- |
| 範本                    | `name`           | 是   | 範本名稱，最長 200 字；沒有名稱的範本整份略過                                                  |
| 範本                    | `description`    | 否   | 說明，最長 2,000 字，顯示在範本卡片上                                                          |
| 階段 `stages[]`         | `title`          | 否   | 階段名稱，最長 200 字。**相鄰且標題相同的步驟屬於同一階段**，建議寫成「階段 N：…」             |
| 階段                    | `steps[]`        | 是   | 這個階段的步驟，依序執行；每個步驟會在專案裡對應一個任務。沒有任何有效步驟的階段會被丟掉       |
| 階段                    | `relatedPrompts[]` | 否 | 階段「相關提示詞」：不是步驟、不產生任務，只是做這個階段時可隨時複製的輔助提示詞（最多 20 個） |
| 步驟／相關提示詞        | `title`          | 內嵌提示詞時必填 | 步驟名稱，最長 200 字                                                                  |
| 步驟／相關提示詞        | `prompt`         | 與 `itemDefaultId` 二擇一 | 提示詞全文，最長 50,000 字                                                      |
| 步驟／相關提示詞        | `itemDefaultId`  | 與 `prompt` 二擇一 | 引用內建知識庫提示詞的 `defaultId`（例如 `kb-default-024`）；標題可省略，由知識庫項目帶入 |
| 步驟                    | `artifact`       | 否   | 這一步的產出要匯出成 OpenSpec 變更資料夾裡的哪個檔案（例如 `proposal.md`、`specs/general/spec.md`），只接受 `.md` 的相對路徑，不可含 `..` 或絕對路徑 |
| 步驟                    | `useBaseContext` | 否   | `true` 時，這一步的提示詞會帶入專案匯入的 OpenSpec 既有規格                                    |

其他欄位（包含檔案裡的 `id`、`createdAt`）一律忽略。

### 數量上限

| 項目                 | 上限  |
| -------------------- | ----- |
| 一個檔案的範本數     | 50    |
| 一個範本的階段數     | 30    |
| 一個階段的步驟數     | 50    |
| 一個階段的相關提示詞 | 20    |

超過上限的部分會被捨棄（多出來的範本會列為略過）。

## 3. 提示詞裡可以用的標記

- **`{{topic}}`**：建立專案時輸入的「專案主題」，複製提示詞時會自動代換。可以出現多次。
- **`[請填入]`**、**`[待確認：…]`**：慣用的填空與缺資料標記。App 不會處理它們，只是提醒你（或 AI）補資料；
  內建範本與本資料夾的範例都要求 AI「資訊不足時標 `[待確認]`、不要自行編造」。
- 組合給 AI 的完整提示詞會**自動**加上「專案主題」「目前步驟（階段與進度）」「前面步驟的產出」
  （可在階段流程頁選擇帶入全部／只帶上一步／不帶），所以步驟提示詞裡不需要再重複貼這些內容，
  只要寫「見前面步驟的產出」即可。

## 4. 建議的提示詞寫法

本資料夾的範例統一用下面的骨架，AI 的產出比較穩定，也方便你之後整批修改：

```text
# 步驟名稱

## 角色與目標
你是○○顧問，協助我……

## 輸入資訊
- 專案主題：{{topic}}
- 其他需要使用者補的資料：[請填入]

## 輸出要求
1. **項目名稱**：這一項要產出什麼
2. **項目名稱**：……

## 補充
資訊不足的地方請標 [待確認：...]，不要自行編造數據、……
```

撰寫原則：

1. **一個步驟只做一件事**，產出要具體到下一步可以直接使用。
2. **輸出要求用編號清單**，每項寫清楚「是什麼」，而不是「請分析」這類空泛指令。
3. **把禁止編造寫進去**：數據、法規、金額、真實人名與品牌。
4. **階段與步驟順序就是依賴順序**：後面的步驟會自動拿到前面的產出，排序時先放需要「輸入」的步驟。
5. 一個階段 2-4 個步驟、整個範本 3-5 個階段比較好用；太細會讓使用者一直複製貼上。
6. 需要重複使用的輔助內容（檢核表、話術範本）放 `relatedPrompts`，不要硬塞成步驟。

## 5. 驗證規則與常見錯誤

匯入是「寬鬆但安全」：能用的留下，不能用的略過並回報，不會因為一個壞步驟讓整份檔案失敗。

| 情況                                              | 結果                                                       |
| ------------------------------------------------- | ---------------------------------------------------------- |
| 不是合法 JSON、最上層不是範本／陣列／`templates`  | 整份失敗：「這不是有效的專案範本檔」                       |
| `format` 欄位存在但不是 `platter-project-templates` | 整份失敗                                                 |
| 範本沒有 `name`                                   | 該範本略過（`no-name`）                                    |
| 範本沒有任何有效階段                              | 該範本略過（`no-steps`）                                   |
| 步驟沒有 `prompt` 也沒有 `itemDefaultId`          | 該步驟丟掉                                                 |
| 內嵌提示詞的步驟沒有 `title`                      | 該步驟丟掉                                                 |
| 階段裡一個有效步驟都沒有                          | 該階段丟掉                                                 |
| `artifact` 不是安全的 `.md` 相對路徑              | 只丟掉 `artifact` 欄位，步驟保留                           |
| 全部範本都被略過                                  | 失敗：「檔案裡沒有可匯入的範本」，不寫入任何東西           |

小提醒：

- JSON 不能有註解與結尾逗號；字串裡的換行寫成 `\n`、雙引號寫成 `\"`。
- 提示詞很長時，建議用程式或編輯器的 JSON 格式化功能產生，不要手動拼字串。
- 內建的 `itemDefaultId` 若在使用者的知識庫與內建檔都找不到，該步驟在建立專案時會被略過。

## 6. 請 AI 幫你產生範本檔

把下面這段連同你的需求貼給 AI，再把輸出存成 `.json` 匯入即可：

```text
請依下列格式產生一份 Platter 專案範本檔（只輸出 JSON，不要加說明或 Markdown 程式碼圍欄）。

格式：
{"format":"platter-project-templates","formatVersion":1,"templates":[{"name":"","description":"",
"stages":[{"title":"階段 1：…","steps":[{"title":"","prompt":""}],"relatedPrompts":[{"title":"","prompt":""}]}]}]}

規則：
1. 3-5 個階段，每階段 2-4 個步驟；階段標題用「階段 N：名稱」。
2. 每個 prompt 用這個骨架：# 標題／## 角色與目標／## 輸入資訊（第一項「專案主題：{{topic}}」，其餘用 [請填入]）／## 輸出要求（編號清單，每項 **粗體名稱**：說明）／## 補充（資訊不足標 [待確認：...]，不要自行編造數據、法規或金額）。
3. 後面的步驟會自動帶入前面步驟的產出，不需要在提示詞裡重複貼上內容。
4. 輸出必須是合法 JSON（無註解、無結尾逗號）。

我的需求：
- 領域與用途：
- 專案主題的例子：
- 希望涵蓋的階段或交付物：
- 不要出現的內容（品牌、數據、法規等）：
```

這些範例是通用骨架：金額、數據、法規與稅務處理一律由使用者提供或標「待確認」，

請依自己的產業與公司制度調整後再使用。
